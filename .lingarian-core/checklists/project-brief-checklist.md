# Project Brief Creation Checklist

This checklist ensures comprehensive project brief creation that enables autonomous downstream processing. Based on the create-project-brief.md command process.

## Pre-Creation Validation

### Information Gathering Completeness
- [ ] Project idea clearly articulated (what the application should do)
- [ ] Problem statement defines specific user pain points
- [ ] Target audience clearly identified (who will use the app)
- [ ] Core functionality requirements gathered
- [ ] Feature prioritization completed (must-have vs. nice-to-have)
- [ ] Visual and experience preferences collected
- [ ] Business objectives and goals defined

### User Story Requirements
- [ ] At least 5-7 user stories collected in plain language
- [ ] User stories follow "As a [user], I want [goal] so that [benefit]" format
- [ ] Each user story addresses specific user needs
- [ ] User stories cover core application functionality
- [ ] User stories are actionable and testable

## Template Compliance Validation

### Required Sections Completeness
- [ ] **Project Overview**: Clear 1-2 sentence summary provided
- [ ] **Problem Statement**: Articulates specific user pain points
- [ ] **Proposed Solution**: Explains how the app solves the problem
- [ ] **Target Audience**: Clearly defines who will use the app
- [ ] **User Stories**: At least 5-7 stories in proper format
- [ ] **Goals**: Include measurable business objectives
- [ ] **MVP Scope**: Clearly separates must-have from nice-to-have features
- [ ] **Visual Style Preferences**: Specified design direction
- [ ] **Additional Notes**: Captures any special requirements

### Information Quality Standards
- [ ] All sections contain sufficient detail for planning phase
- [ ] Information is specific enough to avoid ambiguity
- [ ] Business requirements are clear and actionable
- [ ] MVP scope is realistic and well-defined
- [ ] Technical requirements can be inferred from business needs

## Missing Information Protocol

### Validation Process
- [ ] Identify any sections lacking sufficient detail
- [ ] Revisit incomplete topics with specific follow-up questions
- [ ] Provide relevant examples to help articulate needs
- [ ] Ensure all sections meet minimum requirements before proceeding
- [ ] Verify brief enables autonomous downstream processing

### Success Criteria Validation
- [ ] Brief contains enough detail for plan-project.md agent to generate comprehensive user stories
- [ ] All business requirements are clear and actionable
- [ ] MVP scope is realistic and well-defined
- [ ] Technical requirements can be inferred from business needs
- [ ] User stories are implementable and testable

## Final Output Validation

### Document Generation
- [ ] docs/project_brief.md created following exact template structure
- [ ] All template sections meaningfully populated
- [ ] Information specific enough to avoid planning phase ambiguity
- [ ] User stories are actionable and testable
- [ ] MVP scope realistic for platform capabilities

### Handoff Readiness
- [ ] Brief enables autonomous downstream processing
- [ ] All sections meet quality standards
- [ ] User approval obtained for final brief
- [ ] Next steps in automated pipeline communicated
- [ ] Document ready for project planning phase

## Communication Quality Gates

### User Experience Standards
- [ ] Process kept simple and user-friendly for non-technical users
- [ ] One main question asked at a time
- [ ] Examples and analogies provided when needed
- [ ] Regular summarization and confirmation of understanding
- [ ] Supportive tone maintained throughout process
- [ ] User confidence built through encouragement

### Information Accuracy
- [ ] All gathered information accurately captured
- [ ] User intent properly understood and documented
- [ ] Technical implications considered for business requirements
- [ ] Feasibility considerations noted where appropriate
